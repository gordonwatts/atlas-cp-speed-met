# Framework and standalone integration

The reference is the stock MET algorithm sequence in AnalysisBase 25.2.117. The first replacement keeps the boundaries at which the framework rebuilds MET terms, varies the track soft term, builds the total, and evaluates significance. Each boundary can be tested on a real event before combining any of its work. The designs below describe implementation targets. ## Data transport

The framework adapter owns StoreGate lookup, nominal selected views, association and target extraction, output decoration, and translation of statuses. The standalone adapter owns uproot reads, Awkward offsets, collection-key and index decoding, and histogram filling. Both adapters must preserve unselected original objects when their records are referenced elsewhere. Nominal selection and calibration values needed by the standalone adapter must be derived from the original file. A reference ntuple can supply expected values in a checker.

Three nominal preparation steps require direct tests. The job updates NNJVT. Its new pass decoration differed from the stored decoration for two jets in the first 16 events. The tau block runs its smearing algorithm even on PHYSLITE. Its nominal momenta agreed with stored values in those 16 events, including three selected taus. The photon block applies the primary-vertex origin correction before the optional energy calibration. For a preselected photon it reads the first cluster's layer-1 eta, computes the shower depth, subtracts the primary-vertex z and writes the corrected pT and eta as floats. Six raw photon transverse momenta differed from their prepared values in the first 16 entries. The full observer must cover selected photons. Fixed nominal inputs across MET states still require reproduction of these calculations where active. At CorrectionLib develop `3dcfa20ec01fb40c4d5fec58383785519dec1c00` the v4 plugin interface accepts typed scalar inputs or batches and fixed-size output rows. Ragged association rows and a variable number of links need an explicit lifetime. A candidate integration can bind immutable, typed rows for the duration of evaluation and pass an event index to the registered node. The native event operation remains callable independently for tests. Check nested calls and a failed event followed by a successful one before enabling reuse. ## Soft-term tests

1. Resolve the release TEnv file, units and three TH3D objects offline. The stock tool finds the three bin indices on the shift histogram and uses those indices for the resolution tables. Check equality of the three axis definitions before compiling them as independently addressed tables. Clamp only the hard-recoil upper overflow.
2. The configured MC algorithm seeds from the integer truncation of one million times the uncorrected soft-term azimuth. Preserve the signed conversion to the unsigned public setter and its explicit zero-to-one rule. Under nominal the soft correction exits before drawing. Every active scale or resolution call draws one Gaussian. The separate correlated resolution uses the same draw on both axes.
3. Start recoil from the truth non-interacting term and subtract every non-soft, non-total reconstructed term in source order. The coefficient sign for transverse projection is fixed by the source. The tool applies the projection twice, with a shift in between. Check a negative component on each axis, zero recoil, the source's sumET guard, and missing truth separately. Preserve source return codes and any nonfinite classifications.
4. Compare each varied soft term from the replacement to the stock corrected term, then compare the Final sum and significance after propagation. A correct table value alone cannot establish any of those three comparisons. [Original soft-term code](source/METSystematicsTool.cxx) · [Original caller and seed](source/MetMakerAlg.cxx)

The trial for reuse across states comes after the faithful measurement. Share the hard reconstruction only if the immutable inputs, flags, links, statuses and pre-shift soft term agree in every state. The varied Final direction still enters the covariance rotation. [Trial register](optimization.md)

Check each of these branches on every original row before comparing the selected views. Then compare the ordered selected original identities with A. A failed early cut can otherwise hide a difference in the meaning of a downstream bit. Two checks determine which original electron and photon leaves C must read. The dead-HV tool retrieves the first cluster's eta and phi in the calorimeter frame and the random run number on simulation before testing its run windows. A missing frame moment returns false. The calorimeter isolation tool first checks for the stored leakage-correction field for each cone. When it is present with a stored isolation sum, the tool replaces the old leakage and can add its Run 3 core-timing term from `Eadded_Lr2` and `Eadded_Lr3`. The initialized electron and photon leakage files differ. Confirm actual field presence and compare the reached numerical path on this file.
